# AI와 함께 학습하며 구현하기

참가자가 질문하고 설계를 선택하며 핵심 코드를 작성합니다. AI는 각 단계에서 선택지를 설명하고, 막힌 부분에 힌트를 주고, 테스트와 리뷰를 함께합니다.

저장소를 연 AI 코딩 도구에서는 **“뭐 해야 해?”**라고 묻는 것으로 시작할 수 있습니다. 아래 프롬프트는 단계별 도움을 자세히 요청하고 싶을 때 사용합니다.

## Step 1 — 언어 선택과 실행 뼈대

```text
AGENTS.md와 docs/ASSIGNMENT.md를 읽으십시오. 제가 언어를 아직 지정하지 않았다면
먼저 원하는 언어를 물어보십시오. 선택한 언어로 solution/에 main 또는 실행 진입점,
기본 JSONL 연결, 빌드 설정과 첫 구현 파일을 실제로 만드십시오.
데이터 모델과 ObjectPool 시그니처를 만들고 핵심 로직에 TODO를 남겨 주십시오.
초기 코드의 빌드와 실행을 확인하고 제가 열 파일, 첫 TODO, 실행 명령을 알려 주십시오.
```

## Step 2 — 설계 선택과 테스트 작성

```text
제가 생각 중인 동작과 설계를 물어보십시오. 소유권·자료구조·용량 정책의
선택지와 장단점을 설명하고, 제가 핵심 로직의 설계와 첫 구현 단계를 고르게 도와주십시오.
같은 인스턴스 재사용, 새 속성으로 초기화, 중복 반환 후 풀 상태의
입력과 기대 결과를 함께 정한 뒤, 실행 가능한 테스트를 같이 작성하십시오.
구현 TODO로 실패하는 항목을 표시하고 첫 실패를 함께 읽어 주십시오.
공통 계약과 검증기 파일은 변경하지 마십시오.
```

## Step 3 — 직접 구현 후 리뷰

```text
제가 작성한 ObjectPool을 코드 리뷰해 주십시오.
객체 동일성·이중 반환·초기화 누락·수명 문제를 중점 검사하고,
실패를 재현하는 입력과 기대 결과를 먼저 짚어 주십시오.
질문이나 힌트로 제가 수정하도록 도와주고, 코드 예시를 요청하면
문제가 생긴 부분만 함께 작성하며 어떤 동작이 달라지는지 설명해 주십시오.
```

## Step 4 — 검증 및 발표

```text
.github/workflows/solution-<lang>.yml에서 PR의 빌드(필요 시),
언어별 단위 테스트, 오프라인 JSONL 검증을 실행하십시오.
빌드와 검증 명령을 solution/README.md에 기록하십시오.
실행한 명령과 통과·실패·미실행 항목을 구분해 보고하고
발표용으로 자료구조 선정 이유, 오류 사례, 트레이드오프를 간단히 정리하십시오.
```

## 체크 사항

- 내가 선택한 자료구조와 객체 수명 정책을 설명하고, 작성한 코드와 테스트를 직접 실행해 봅니다.
- 생성된 코드가 맞다는 말 대신 단위 테스트와 로그로 확인합니다.
- AI가 `docs/PROTOCOL.md` 또는 검증기를 고치자고 제안하면 먼저 규격 위반인지 확인합니다.
- 도구가 환경 명령을 실행하지 못하면 성공했다고 보고하지 않습니다.
- GitHub Actions에 언어별 빌드/테스트 job을 추가합니다. 공통 CI만 통과했다고 언어별 솔루션이 정상 실행된 것은 아닙니다.
